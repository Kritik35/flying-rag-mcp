## 44.12. Сквозные политики и STOP-инварианты
DATA: никаких destructive работ с production SQLite/LanceDB без отдельной команды; архивы и эталон 006A не менять.
CPU: на Acer каждый тяжёлый запрос требует действительных HWiNFO, thermal gate, watchdog и concurrency; timeout внешнего Lemonade не гарантирует немедленный аппаратный stop.
IDEMPOTENCE: повторный запуск/обновление не меняет логические записи без новых данных; измерять по ID и структуре, не только общему размеру.
PARITY: ASUS 기능 не потерять, 12 MCP schemas не равны полной функциональной совместимости.
EVIDENCE: PASS только при исполняемых тестах, RAW, SHA/версиях; ошибочные старые отчёты сохранять с пометкой corrected.
LANCE: Acer pin 0.39; ASUS до G4 pin 0.33; после upgrade отдельный lock. Не записывать разными версиями в одну физическую базу.
RECOVERY: все необратимые миграции только со snapshot, tested restore и operator window.
CLEANUP: только после ввода обеих машин, dry-run, аудит и пообъектное разрешение.
Для всех этапов указывать выполненное/непроверенное, полный SHA и ссылку evidence, запрещать автоматическое продвижение между Gate и автоматическую очистку.
