# Защитный апгрейд FlyingRAG без записи в датасеты

## Цель

Устранить подтверждённые риски безопасности и целостности данных без чтения,
изменения или переиндексации рабочих датасетов.

## Неподвижные ограничения

- Никаких операций над рабочими LanceDB, `metadata.db`, `engineering_rules` и semantic cache.
- Никаких запусков watcher, indexer, backfill или reindex на рабочем корпусе.
- Все тесты записи используют только `TemporaryDirectory` и временные SQLite-файлы.
- Размерность embeddings, chunking, схема векторного индекса и retrieval ranking не меняются.
- Публичные MCP-интерфейсы сохраняют обратную совместимость, кроме отказа индексировать путь вне allowlist.

## Архитектура

### 1. Граница разрешённых путей

`reindex_path` разрешает только существующие файлы и каталоги внутри
`watched_folders` после канонического `resolve`. Проверка выполняется до запуска
subprocess. Символические ссылки и `..`, выводящие путь за корень, отклоняются.

### 2. Единственный writer watcher

Watcher передаёт изменения одному последовательному worker. Повторные события
одного канонического пути объединяются. Worker ожидает завершения `indexer.py`
и только затем берёт следующую задачу, исключая конкурентную запись в хранилища.

### 3. Атомарный rules backfill

Новые правила сначала извлекаются в памяти. Существующие строки заменяются одной
транзакцией только после полного успешного извлечения файла. Любая ошибка оставляет
старый набор нетронутым и отражается статусом `failed` или `partial`.

### 4. Локальная сеть, cache generation и безопасные ошибки

Клиенты localhost не изменяют process-wide proxy environment. Semantic cache
получает поколение корпуса в scope. MCP возвращает безопасные коды ошибок без
абсолютных путей; подробности остаются в stderr/ротационном журнале.

## Тестирование

Каждое исправление выполняется через RED → GREEN. Запрещены mocks рабочих баз;
для SQLite применяются временные реальные файлы, subprocess и index operations
подменяются на границе вызова. После targeted-тестов запускается базовый набор
из 58 тестов и `git diff --check`.

## Не входит в эту волну

Evidence contract, file cards, runtime admission, новый embedder, late chunking,
contextual retrieval, ColPali и любые миграции существующего корпуса.
