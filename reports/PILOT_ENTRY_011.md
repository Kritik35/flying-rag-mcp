## 2. План создания изолированной копии (Consistent Independent Snapshot)

> [!CAUTION]
> В таблицах базы `metadata.db` присутствуют структуры `search_cache` и `semantic_cache`. Выполнение любых поисковых запросов через сервер RAG инициирует транзакции записи в кэш. Запуск поисковых испытаний по оригинальным файлам production **категорически запрещён**, так как приведёт к мутации боевой базы.

### 2.1. Методология создания снимка (без вмешательства в production)
1. **Координация с оператором**:
   - Фиксация момента создания снимка при отсутствии активных внешних сессий импорта.
   - Проверка: `metadata.db-wal` отсутствует или равен 0 байт.
2. **Изолированный целевой каталог**:
   - `C:\Acer_System_Audit\rag_quality_ab_20261113\isolated_pilot_data` (вне git-репозитория и вне каталога `data_imported`).
   - Использование hardlink, symlink или junction **строго исключено** (только физическое посегментное копирование).
3. **Последовательность копирования**:
   - Шаг 1: Чтение `metadata.db` в бинарном режиме и запись в изолированный каталог `isolated_pilot_data\metadata.db`.
   - Шаг 2: Выполнение `PRAGMA integrity_check` на скопированном изолированном файле.
   - Шаг 3: Рекурсивное копирование директории `lancedb` и манифеста версий.
   - Шаг 4: Копирование каталога `table_parquet`.
4. **Конфигурационная изоляция**:
   - Создание изолированного файла конфигурации `configs/config_pilot_isolated.yaml`.
   - Переопределение всех путей: база метаданных, векторный индекс, кэш запросов, логи сессий — строго внутрь `isolated_pilot_data`.
   - Проверка через `check_readonly_scope()`: боевой каталог `C:\RAG_Acer\data_imported` объявляется аппаратно недоступным для записи.

### 2.2. Матрица рисков и предохранители (STOP Guards)
- `STOP: PRODUCTION_MUTATION_RISK`: Если хотя бы один путь конфигурации ссылается на боевой каталог `C:\RAG_Acer\data_imported`.
- `STOP: WRITERS_ACTIVE`: Если перед копированием обнаружен активный процесс индексации или сторонний дескриптор записи к `metadata.db`.
- `STOP: DISK_SPACE_LOW`: Если свободное место на диске `C:\` опустится ниже 15 GB.
- `STOP: SNAPSHOT_CORRUPT`: Если `PRAGMA integrity_check` на изолированной копии вернёт ошибку.

### 3.1. Критерии оценки результатов
Для каждого запроса проверяются:
1. **Точное соответствие документа и редакции**: Выделение актуального СП и отметка `SOURCE_NOT_VERIFIED` при отсутствии подтверждённого первоисточника.
2. **Идентификатор фрагмента (Chunk ID)** и диапазон страниц/разделов.
3. **Полнота цитаты**: Наличие точных числовых значений (пределы EI, расходы воздуха, коэффициенты) без искажения смысла.
4. **Сравнение EIG OFF vs EIG ON**:
   - `off_rank1_doc` / `off_rank1_chunk` против `on_rank1_doc` / `on_rank1_chunk`.
   - Задержка поиска (`latency_ms`).
   - Факт вызова графа EIG (`eig_invoked = True/False`).
   - Статус CRAG-верификации и факт извлечения таблиц из parquet.
   - Экспертный вердикт: `BETTER` / `SAME` / `WORSE` / `BROKEN`.

## 4. Проверка совместимости модели эмбеддингов

- **Сервер**: `http://127.0.0.1:8089` (llama-server с моделью `Qwen3-Embedding-0.6B-Q8_0.gguf`).
- **Размерность вектора**: 1024.
- **Важное разграничение**: Факт совпадения размерности (1024) **не является доказательством идентичности модели** весам, на которых строился боевой индекс LanceDB (`MODEL_INDEX_IDENTITY=UNVERIFIED`).
- **Требуемое действие**: При авторизации пилота выполнить замер косинусного сходства для контрольной пары токенов из индекса для подтверждения математической совместимости векторов перед сравнением качества EIG.
