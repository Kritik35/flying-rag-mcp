## 1. Анализ ключевых замечаний аудитора (P0-A .. P1-F)

### 1.1. P0-A — Согласованность метода создания снимка (Snapshot Method)
- **Проблема**: Последовательное бинарное копирование SQLite (`metadata.db`), каталога LanceDB и Parquet-таблиц не атомарно. Если между копированием SQLite и LanceDB произойдёт запись (даже при нулевом WAL в начале), снапшоты рассинхронизируются.
- **Подтверждённый регламент**:
  1. *Quiescent Window*: Контроль отсутствия активных writer-процессов (`writers_count == 0`), подтверждение read-only флагов.
  2. *SQLite Backup API*: Для исключения гонок с WAL создание консистентного слепка SQLite должно осуществляться через поддерживаемую процедуру SQLite Online Backup API (`sqlite3.Connection.backup`) или `VACUUM INTO`, формирующую транзакционно замороженный файл без блокировки читателей.
  3. *Хеширование каталога LanceDB*: Фиксация дайджестов файлов LanceDB до и после копирования.
  4. *Кросс-хранилищная валидация*: До выполнения любых поисковых вызовов копия должна проверяться на отсутствие рассинхронизации ссылок между `metadata.db` и `lancedb`.
  5. *Статус*: До реализации транзакционного API метод помечается **`SNAPSHOT_METHOD: UNVERIFIED`** / **`SNAPSHOT_READY: NO_GO_UNTIL_CROSS_STORE_LOCK`**.

### 1.5. P1-E — Инвариант теневого режима EIG (Shadow EIG Invariance)
- Архитектурный инвариант: Теневой EIG работает в пассивном режиме наблюдения и **не имеет права изменять клиентскую выдачу или порядок ранжирования**.
- Любое изменение рангов или нормализованного payload между режимами OFF и ON классифицируется как **регрессия (`SHADOW_REGRESSION_STOP`)**.
- Во всех проведённых вызовах соблюдено полное совпадение (`rank_and_payload_identical: True`).
