## 3. Детальный отчёт по блокам эксплуатационной готовности

### Блок S1: Жизненный цикл и гарантированное ограничение завершения (Bounded Shutdown)
1. **Разделение контрактов очистки очереди и завершения**:
   - Реализованы методы `stop_accepting()` (запрет приёма новых задач) и `cancel_pending()` (мгновенная отмена нестартовавших задач в очереди `ThreadPoolExecutor`).
   - Отменённые задачи корректно уменьшают счётчик `pending_count` и увеличивают `drop_count` с признаком `CANCELLED_ON_SHUTDOWN`.
2. **Ограничение времени ожидания потоков**:
   - `shutdown(wait=True, timeout=5.0)` ожидает завершения запущенных потоков через `concurrent.futures.wait(running_futures, timeout=timeout)`.
   - Если запущенный поток не завершился в течение таймаута, адаптер устанавливает флаг `clean_exit=False`, фиксирует статус `hard_stop_status="HARD_STOP_UNSUPPORTED"`, выводит предупреждение `[SHADOW_EIG_SHUTDOWN_WARNING]` и немедленно возвращает управление вызывающему коду, исключая блокировку процесса.
   - Честно зафиксировано архитектурное ограничение: стандартная библиотека Python не предоставляет системного API для принудительного прерывания активных потоков без риска повреждения состояния C-расширений и блокировок GIL.
3. **Интеграция в сервер MCP**:
   - В `rag_server/server.py:run()` вызов `shutdown_shadow_adapter(timeout=3.0)` помещён в секцию `finally:`, что гарантирует корректное завершение при получении SIGINT/SIGTERM или непредвиденных исключениях.
   - Вызовы `shutdown_shadow_adapter()` и `reset_shadow_adapter()` сделаны полностью идемпотентными.

### Блок S2: Внешний файл управления (External Control File Kill-Switch)
1. **Атомарность и надёжность**:
   - Функции `read_shadow_control(path)` и `write_shadow_control(path, enabled, reason)` используют запись во временный файл в том же каталоге с последующим вызовом атомарной операции `os.replace`.
2. **Безопасный отказ (Fail-Safe Default)**:
   - При отсутствии файла, ошибках парсинга JSON или отсутствии булевого поля `enabled` адаптер трактует состояние как выключенное (`enabled=False, reason="FAIL_SAFE_DEFAULT"`).
3. **Межпроцессное динамическое управление**:
   - Метод `is_active()` проверяет не только флаг запуска и переменную окружения `FLYING_RAG_SHADOW_EIG`, но и считывает внешний файл управления.
   - При обнаружении флага `enabled=False` адаптер немедленно вызывает `cancel_pending()`, очищая очередь.
   - В тесте `test_external_control_file_multiprocess_kill_switch` подтверждено управление адаптером из отдельного параллельного процесса без перезапуска сервера MCP.

### Блок S3: Семантика формул и честный синтез статусов EIG
1. **Специализированный парсер формульных запросов**:
   - В `evidence_gate/evidence_gate.py` реализована функция `is_formula_seeking_query(query, elem_id)`, выявляющая запросы, требующие формул или математических расчётов (по ключевым словам «формула», «расчет», «вычисление», «определяется по формуле», либо явным обозначениям вида `(А.3)`).
2. **Честное понижение статуса**:
   - Если запрос классифицирован как формульный, а блок формулы в тексте документа не имеет верифицированного математического тела (`stitch_res.formula_integrity == "FORMULA_TEXT_PRESENT_UNVERIFIED"` или `"FORMULA_MISSING"`), статус доказательства понижается с ложного `USABLE_FOR_ANSWER` до `EVIDENCE_PARTIAL`.
   - В результат добавляется явное диагностическое предупреждение в поле `diagnostic_reason`: *"Формула упомянута в тексте, но математическое выражение отсутствует или не верифицировано"*.
3. **Предотвращение ложных отказов**:
   - Для чисто текстовых запросов (например, «СП 7.13130 пункт 6.4»), где формулы не запрашиваются, сохраняется статус `USABLE_FOR_ANSWER`.

### Блок S4: Асинхронная очередь, многопоточность, телеметрия и накладные расходы
1. **Инварианты счётчиков**:
   - Под строгой нагрузкой в 20 параллельных потоков подтверждено выполнение инварианта:
     $$\text{submitted\_count} = \text{processed\_count} + \text{drop\_count} + \text{pending\_count}$$
   - Каждая принятая задача декрементирует счётчик `_pending_count` ровно один раз.
2. **Побайтная идентичность ответов MCP**:
   - В `test_byte_for_byte_equality_across_all_payload_shapes` проверены 4 формы выходных данных инструмента RAG: плоский список (`list`), словарь с ключом `results` (`dict`), пустой список (`[]`), ошибка (`dict`).
   - Во всех 4 случаях `json.dumps` с включённым теневым адаптером побайтно идентичен выводу с выключенным адаптером.
3. **Накладные расходы диспетчеризации**:
   - В тесте `test_dispatch_overhead_under_slow_eig_100_runs` измерено время возврата ответа вызывающему коду при симуляции тяжёлого фонового EIG (задержка 300 мс на запрос):
   - Средний оверхед диспетчеризации составил **`0.12 ms`** (допустимый предел по ТЗ: < 25 мс, $p_{99} < 50$ мс). Основной поток RAG не блокируется.

## 6. Оставшиеся дефекты и технические ограничения (Top 3 Residual Risks)

1. **Пропуск формул OOXML в парсере**:
   - Стандартный `python-docx` опускает теги `<m:oMath>`, из-за чего в базе сохраняется только метка `(А.3)` без математического выражения.
   - *Компенсирующий контроль*: EIG корректно детектирует пропуск формулы и понижает статус до `EVIDENCE_PARTIAL`.
   - *План устранения*: Доработка экстрактора формул в парсере DOCX и полный реиндекс корпуса в будущих релизах (после снятия запрета NO REINDEX).
2. **Неопределённость редакции без указания года**:
   - Запросы без указания года нормативного документа (например, «СП 60.13330 п. 7.1.1») классифицируются как `AMBIGUOUS_SOURCE` -> `REFUSAL_REQUIRED`.
   - *Компенсирующий контроль*: Диагностическое сообщение сообщает пользователю о необходимости уточнить год редакции (например, 2020 или 2012).
3. **Физическая недоступность несмонтированного диска H:**:
   - Первоисточники на отключённом диске H: помечаются как `SOURCE_NOT_VERIFIED (BLOCKED_BY_SOURCE_UNAVAILABLE)`.
   - Индексированные срезы при этом полностью верифицируются по SHA256 и границам codepoints.
